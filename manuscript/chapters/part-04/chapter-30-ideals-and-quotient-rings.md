# Chapter 30 — Ideals and Quotient Rings

> **Audience.** This chapter assumes familiarity with commutative rings, ring homomorphisms, subgroups, and quotient types. It develops the ideal and quotient-ring interfaces used to express congruence modulo an ideal and to construct induced maps.

An ideal packages two kinds of structure at once: additive closure and absorption under multiplication by arbitrary ring elements. A quotient ring then identifies two elements when their difference belongs to the ideal. Mathlib organizes this development around `Ideal R`, the quotient notation `R ⧸ I`, and the canonical quotient map. The first isomorphism theorem and quotient universal property should be used as library interfaces rather than reproved through representatives.

The chapter connects the quotient reasoning of Chapter 9 with the bundled maps of Chapter 13. It also provides the algebraic infrastructure needed for polynomial quotient rings, modular arithmetic, and the Chinese remainder theorem.

## Learning objectives

By the end of the chapter, you should be able to:

- use `Ideal R` as a bundled subobject of a commutative ring;
- translate equality in `R ⧸ I` into membership of a difference in `I`;
- define maps out of a quotient through `Ideal.Quotient.lift`;
- apply the first isomorphism theorem using a homomorphism's kernel;
- connect prime or maximal ideals to domain and field structures on quotients.

## 1. Ideals combine additive and multiplicative closure

For a commutative ring `R`, an ideal `I : Ideal R` is an additive subgroup that absorbs multiplication by elements of `R`. The structure includes the closure rules required by ring operations, so membership goals should normally be solved with the ideal API rather than by expanding the full structure.

Ideals are ordered by inclusion and form a complete lattice. The bottom ideal contains only zero; the top ideal is all of `R`. Meets express intersections, while joins express the ideal generated by the ideals being combined. In a commutative ring, notation such as `I + J` corresponds to the lattice join `I ⊔ J`.

This order structure is useful when a proof must compare congruences. If `I ≤ J`, then congruence modulo `I` is finer than congruence modulo `J`, and there is a natural map from `R ⧸ I` to `R ⧸ J`. State the inclusion in the ideal lattice; do not replace it with a hand-written pointwise membership implication unless the local goal requires that form.

The ideal generated by a set is `Ideal.span`. It is the least ideal containing that set, which gives a useful interface for ideals specified by generators. Membership in a span may be less transparent than membership in an already named ideal; use the generated-set theorem when constructing the ideal and specialized lemmas when reasoning about its elements.

For two ideals, membership in their join has a concrete witness form: an element is a sum of one member from each ideal. This is the additive part of the generated ideal; closure under multiplication is already supplied by each ideal. The witness form is useful when proving a pointwise statement, while the order form `I ≤ J` is usually better for composing quotient constructions.

```lean
example {R : Type*} [CommRing R] (I J : Ideal R) (x : R) :
    x ∈ I ⊔ J ↔ ∃ y ∈ I, ∃ z ∈ J, y + z = x := by
  simp [Submodule.mem_sup]
```

This is a good example of choosing a representation only at the boundary where it helps. The theorem statement uses lattice notation; a proof that needs actual summands can rewrite to the existential form and continue with the witnesses.

## 2. The quotient map and congruence modulo an ideal

The quotient `R ⧸ I` identifies elements whose difference lies in `I`. Mathlib supplies a canonical ring homomorphism:

```lean
example {R : Type*} [CommRing R] (I : Ideal R) :
    R →+* R ⧸ I :=
  Ideal.Quotient.mk I
```

Its kernel is exactly `I`. Equality in the quotient is therefore a congruence statement:

```lean
theorem exercise_30_2_quotient_eq_iff_sub_mem
    {R : Type*} [CommRing R] (I : Ideal R) (x y : R) :
    Ideal.Quotient.mk I x = Ideal.Quotient.mk I y ↔ x - y ∈ I := by
  exact Ideal.Quotient.mk_eq_mk_iff_sub_mem x y
```

This is often the main rewrite step in a quotient proof. Instead of choosing representatives for quotient elements, move to a statement about the difference in the original ring. For proving equality in a quotient, show that difference belongs to the ideal. For extracting information from an equality of classes, apply the same equivalence in the reverse direction.

The canonical map is surjective: every quotient element has a representative. It is usually unnecessary to invoke surjectivity manually, because the quotient API already provides ways to reason about arbitrary quotient elements. If a proof does choose representatives, keep the representative-dependent argument local and finish by using a theorem that does not depend on the choice.

## 3. Quotient maps as a universal property

Suppose a ring homomorphism `f : R →+* S` sends every element of `I` to zero. Equivalently, `I ≤ RingHom.ker f`. Then `f` factors uniquely through the quotient by `I`:

```lean
example {R S : Type*} [CommRing R] [CommRing S]
    (I : Ideal R) (f : R →+* S)
    (h : I ≤ RingHom.ker f) : R ⧸ I →+* S :=
  Ideal.Quotient.lift I f h
```

This construction expresses the universal property of the quotient. The condition on the kernel is exactly what makes the induced map well-defined: equivalent representatives have differences in `I`, and `f` sends that difference to zero. Once the lift is built, its behavior on representatives is described by a simplification theorem such as `Ideal.Quotient.lift_mk`.

Use the lift when the theorem needs a map from a quotient, rather than defining a function on quotient classes by cases. The latter forces a proof that the function is independent of representative; `Ideal.Quotient.lift` packages that obligation and returns a ring homomorphism with the algebraic laws already proved.

The universal property is also a proof-design guide. To build a map out of `R ⧸ I`, identify the intended map on `R`, then prove that `I` lies in its kernel. To prove two maps out of the quotient equal, it is enough to compare their composites with the quotient map, using the quotient extensionality theorem.

This last step is an instance of a broad extensionality principle: quotient elements are generated by classes of original elements. If two ring homomorphisms agree on every class represented by `r : R`, they agree everywhere. In practice, simplify both composites on `Ideal.Quotient.mk I r`, then prove equality of the resulting maps. This is usually clearer than destructing an arbitrary quotient element.

## 4. The first isomorphism theorem

Every ring homomorphism `f : R →+* S` induces an injective map from `R ⧸ ker f` to the range of `f`. This is the first isomorphism theorem:

```lean
noncomputable example {R S : Type*} [CommRing R] [CommRing S]
    (f : R →+* S) : R ⧸ RingHom.ker f ≃+* f.range :=
  RingHom.quotientKerEquivRange f
```

The quotient removes precisely the information that `f` forgets. The induced equivalence then identifies each equivalence class with its image. This theorem is particularly effective when a problem asks for a classification of a quotient, a cardinality argument, or an algebraic structure on the image.

The proof strategy is to separate the two ingredients: the kernel determines which inputs become identified, and the range records which outputs occur. Avoid proving injectivity of a representative-level map directly unless the kernel calculation is the result of interest. Usually, `RingHom.ker` and `quotientKerEquivRange` already express the complete argument.

For a surjective map, the range is equivalent to the entire codomain. Mathlib has a quotient-by-kernel equivalence specialized to that case. If surjectivity is already available, the specialized theorem may give a cleaner type than an equivalence to a range subtype.

## 5. Ideals, prime quotients, and field quotients

The algebraic properties of a quotient reflect properties of its ideal. For a commutative ring, quotienting by a prime ideal gives an integral domain. Quotienting by a maximal ideal gives a field. The converses hold as well, so these are equivalences that can move a proof between ring structure and ideal structure.

For instance, when a goal concerns whether `R ⧸ I` is a field, inspect the maximality of `I`. The library provides `Ideal.Quotient.maximal_ideal_iff_isField_quotient`. Conversely, if the quotient is already known to be a field, use the reverse direction to prove maximality. This is often simpler than proving directly that every nonzero quotient class is invertible.

These correspondences explain why ideal theory is useful in constructing new fields and domains. For modular arithmetic, the quotient of `ℤ` by the ideal generated by a prime has a field structure. In abstract formalization, the proof can focus on primality or maximality and then use the quotient theorem to obtain the desired algebraic interface.

The quotient by the top ideal is subsingleton, while quotienting by a proper ideal yields a nontrivial quotient ring. A proof that uses `0 ≠ 1` in a quotient should therefore carry the properness hypothesis, often as `I ≠ ⊤`. As elsewhere, the nondegenerate case should be made explicit rather than left for typeclass search to guess.

## 6. Maps of ideals: image and preimage

For a ring homomorphism, ideals can be transported by `Ideal.map` and `Ideal.comap`. The map is generated by the image of the ideal; the comap is the preimage. These operations satisfy an order connection: mapping an ideal below another ideal is equivalent to placing the original ideal below the other's comap.

This connection makes inclusion proofs systematic. If a goal is `Ideal.map f I ≤ J`, it may be easier to prove `I ≤ Ideal.comap f J`. If the map is surjective or injective, stronger map/comap identities are available. Use those hypotheses locally to recover equalities; without them, map and comap need not undo one another.

This API is important for induced quotient maps. A homomorphism can descend from `R ⧸ I` to `S ⧸ J` when the image of `I` is contained in `J`. The quotient map sends equivalent inputs to equivalent outputs precisely under this compatibility condition. State the condition as an ideal inclusion rather than proving representative independence from scratch.

## 7. Iterated quotients and the Chinese remainder theorem

An iterated quotient first identifies elements modulo one ideal, then identifies classes modulo the image of a second ideal. The result is naturally related to quotienting by the join of the two ideals. Mathlib packages this through its double-quotient equivalences. This is a ring-theoretic version of composing equivalence relations: performing two compatible identifications can often be expressed as one quotient by the combined relation.

For coprime ideals, the Chinese remainder theorem identifies a quotient by their intersection with a product of quotients. For finitely many pairwise coprime ideals, the same pattern gives a product decomposition. In applications, this turns a problem modulo a product of relatively prime moduli into a collection of independent problems in smaller quotient rings.

The underlying map sends a ring element to its tuple of residue classes. Its kernel consists of the elements lying in every ideal, hence the intersection. Pairwise coprimality supplies the surjectivity needed to choose representatives with independently prescribed residues. Thinking of the theorem as “kernel plus surjectivity” connects it to the first isomorphism theorem: identify the kernel first, then establish that every target tuple is attained.

When formalizing such a result, first identify the exact ideals and their relation: intersection, product, or join. These are distinct lattice or algebraic operations. Then find the theorem whose hypotheses match the coprimality and quotient convention. Keeping the ideal relation explicit makes it easier to check whether the target should be a product or an iterated quotient.

## 8. A quotient proof workflow

1. Keep the ideal as a named value `I : Ideal R`; avoid replacing it with a raw set.
2. Use `Ideal.Quotient.mk I` for the canonical ring homomorphism.
3. Translate quotient equality with `Ideal.Quotient.mk_eq_mk_iff_sub_mem` or its zero-membership form.
4. To define a map out of the quotient, prove `I ≤ RingHom.ker f` and use `Ideal.Quotient.lift`.
5. For a map's image, use `RingHom.quotientKerEquivRange` after identifying its kernel.
6. For domain or field goals, use the prime or maximal ideal characterizations.
7. For iterated quotients, check whether the relevant ideal operation is an intersection, product, or join.

This workflow follows the mathematical construction and lets the library discharge the representative-independence proofs. It also keeps the type of every map visible, which is useful because quotient notation can hide the exact source and target.

When there are several quotient maps in a proof, write down their source and target before composing them. A map induced by `I ≤ J` goes from `R ⧸ I` to `R ⧸ J`; the direction reverses the intuitive order of “coarseness.” Checking the types prevents a frequent mistake in double-quotient proofs, where the image ideal in the first quotient is not literally the original ideal in `R`.

## 9. Common failure modes

### Quotient equality is handled by choosing representatives

Use the congruence theorem to reduce it to ideal membership. Only choose representatives when the actual representative is needed.

### A map out of a quotient is defined as a raw function

Use `Ideal.Quotient.lift` after proving that the ideal lies in the kernel. The lift returns a ring homomorphism.

### The first isomorphism theorem targets the wrong type

The theorem identifies the quotient by the kernel with the range subtype. Add surjectivity if the desired target is the whole codomain.

### A quotient is assumed to be a field without maximality

Prove the ideal maximal or use the field-to-maximality direction. A proper ideal alone gives nontriviality, not necessarily a field.

### Ideal operations are conflated

Intersection, product, and join encode different constructions. Check the exact theorem statement before simplifying the ideal expression.

## 10. Exercises

1. Prove that the kernel of the canonical map `R →+* R ⧸ I` is `I`.
2. Show that two elements have equal images in `R ⧸ I` exactly when their difference belongs to `I`.
3. Given `f : R →+* S` with `I ≤ RingHom.ker f`, construct the induced ring homomorphism from `R ⧸ I` to `S` and state its value on a class represented by `r`.
4. Apply the first isomorphism theorem to the quotient map itself and simplify the resulting range.
5. Prove that if `I` is maximal, then `R ⧸ I` is a field. State which nontriviality assumptions are already present in the theorem.
6. Explain how `Ideal.map` and `Ideal.comap` express the compatibility condition for a map of quotient rings.
7. Compare an iterated quotient with a quotient by a join. Identify the image ideal that appears in the second quotient.
8. Find the Chinese remainder theorem in the Mathlib quotient API and list its coprimality hypotheses.

## 11. Formalized exercise patterns

These results expose the core quotient interfaces as reusable theorems: the canonical map has kernel `I`, the lift acts on represented classes as intended, maximality characterizes a field quotient, and ideal map/comap form an adjunction.

### Kernel of the quotient map

```lean
theorem exercise_30_1_quotient_map_kernel
    {R : Type*} [CommRing R] (I : Ideal R) :
    RingHom.ker (Ideal.Quotient.mk I) = I := by
  simp
```

### The induced map on quotient classes

```lean
theorem exercise_30_3_lift_mk
    {R S : Type*} [CommRing R] [CommRing S]
    (I : Ideal R) (f : R →+* S)
    (h : ∀ a : R, a ∈ I → f a = 0) (r : R) :
    Ideal.Quotient.lift I f h (Ideal.Quotient.mk I r) = f r := by
  exact Ideal.Quotient.lift_mk I f h
```

The quotient lift removes representative dependence from its definition; this theorem states its value on a canonical representative. The condition `I ≤ RingHom.ker f` in the construction example is the ideal-order form of this zero-on-`I` predicate.

### Maximal ideals and field quotients

```lean
theorem exercise_30_5_maximal_iff_field_quotient
    {R : Type*} [CommRing R] (I : Ideal R) :
    I.IsMaximal ↔ IsField (R ⧸ I) := by
  exact Ideal.Quotient.maximal_ideal_iff_isField_quotient I
```

This equivalence records the exact nontriviality conditions in the library statement instead of hiding them in a field-instance construction.

### Ideal map–comap adjunction

```lean
theorem exercise_30_6_map_le_iff_comap
    {R S : Type*} [CommRing R] [CommRing S]
    (f : R →+* S) (I : Ideal R) (J : Ideal S) :
    Ideal.map f I ≤ J ↔ I ≤ Ideal.comap f J := by
  exact Ideal.map_le_iff_le_comap
```

This is the inclusion criterion used to descend maps between quotient rings: check the image of the source ideal lies in the target ideal, or equivalently check the source ideal lies in its preimage.

## Summary

An ideal packages additive closure and multiplicative absorption. The quotient map identifies elements whose difference lies in the ideal, and its kernel is exactly that ideal. Use `Ideal.Quotient.lift` to construct maps out of quotients, and `RingHom.quotientKerEquivRange` for the first isomorphism theorem. Prime and maximal ideals characterize domain and field quotients. For more elaborate constructions, track ideal images and distinguish intersection, product, and join.
