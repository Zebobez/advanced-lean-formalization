# Chapter 100 — Fully Corrective Frank–Wolfe and Active-Set Optimization

> **Audience.** This chapter assumes the linear-oracle methods and active-set invariants from Chapters 98–99. It develops fully corrective Frank–Wolfe (FCFW), which re-optimizes over the convex hull of a stored collection of atoms after each new oracle call.

Away-step Frank–Wolfe removes one active atom at a time by moving away from it. Fully corrective Frank–Wolfe makes a broader change: after discovering a new atom, it optimizes over the entire correction polytope generated by the stored atoms. This may require solving a nontrivial restricted problem, but the resulting point can adjust all active weights at once.

The important proof-engineering idea is to specify what the correction routine must guarantee rather than expose its numerical method. An exact restricted minimizer is one implementation. An approximate solver can also be used if it makes at least the progress of a Frank–Wolfe line search and returns a sufficiently small active-set gap.

## Learning objectives

After this chapter, you should be able to:

- define the correction polytope separately from the active support;
- state the exact fully corrective update and derive its first-order certificate;
- formalize an approximate correction by progress and active-gap guarantees;
- distinguish global stopping certificates from restricted stationarity;
- explain why fully corrective methods can have a good-step guarantee at every iteration;
- design Lean interfaces that hide the solver while exposing the facts needed by convergence proofs.

## 1. Correct over a stored set of atoms

### 1.1 Correction set and active support

Let \(A\) be a finite set of atoms and \(P=\operatorname{conv}(A)\). At time \(t\), maintain a correction set \(C_t\subseteq A\) and a point

\[
x_t\in\operatorname{conv}(C_t).
\tag{100.1}
\]

Choose a representation
\[
x_t=\sum_{v\in S_t}\lambda_v^{(t)}v,
\qquad
\lambda_v^{(t)}>0,\qquad
\sum_{v\in S_t}\lambda_v^{(t)}=1,
\tag{100.2}
\]
where \(S_t\subseteq C_t\) is its active support. The correction set and active support are different pieces of state. An atom can remain available for future correction while its current coefficient is zero; in that case it belongs to \(C_t\) but not to \(S_t\).

Call the collection \(C_t\) a correction set because it defines the restricted feasible region. Some algorithms keep every atom ever discovered, so \(C_t\) grows monotonically. Others compress or replace the correction set while retaining the current active support. The convergence interface should depend only on the stated relationship between \(x_t\), its active representation, and the next correction.

### 1.2 The global oracle still controls termination

At \(x_t\), call the linear minimization oracle over all of \(A\):

\[
s_t\in\arg\min_{s\in A}\langle\nabla f(x_t),s\rangle.
\tag{100.3}
\]

The Frank–Wolfe gap is

\[
g_t^{\mathrm{FW}}
=\langle\nabla f(x_t),x_t-s_t\rangle.
\tag{100.4}
\]

For convex \(f\), this is a global optimality certificate: it upper-bounds \(f(x_t)-f(x^\star)\) for a minimizer \(x^\star\in P\). If the gap is at most a requested tolerance, the algorithm can stop. A restricted minimizer over \(\operatorname{conv}(C_t)\) alone cannot certify global optimality, because an undiscovered atom may still improve the objective.

The global oracle has a distinct role in each iteration: it searches for an atom outside the current correction set that can improve the restricted solution. If it returns an atom already in \(C_t\), the correction set need not grow; the correction step may still improve the weights of its current atoms.

## 2. Exact fully corrective updates

### 2.1 Add an atom, then minimize

A simple exact version forms
\[
C_{t+1}=C_t\cup\{s_t\}
\tag{100.5}
\]
and solves the restricted problem

\[
x_{t+1}\in\arg\min_{x\in\operatorname{conv}(C_{t+1})} f(x).
\tag{100.6}
\]

The old point \(x_t\) and the new oracle atom \(s_t\) both belong to this correction hull. Therefore every point on the Frank–Wolfe segment
\[
x_t+\gamma(s_t-x_t),\qquad 0\le\gamma\le1,
\]
is feasible for the restricted problem. Exact correction consequently satisfies

\[
f(x_{t+1})
\le
\min_{\gamma\in[0,1]}f\bigl(x_t+\gamma(s_t-x_t)\bigr).
\tag{100.7}
\]

This inequality is the first key interface property. It says that the correction routine cannot do worse than the ordinary line-search update. It does not claim that correction is computationally cheap.

If \(f\) is continuous and \(C_{t+1}\) is finite, its convex hull is compact, so an exact restricted minimizer exists. If \(f\) is strictly convex, the minimizer as a point is unique, though its representation by atoms can still be nonunique. A numerical solver may return approximate coefficients; then one must establish feasibility and an objective guarantee rather than silently treating its output as an exact argmin.

### 2.2 Restricted optimality controls the active gap

Define the active-set away gap using the negative gradient:

\[
g_t^{\mathrm A}
=\max_{v\in S_t}
\langle-\nabla f(x_t),x_t-v\rangle.
\tag{100.8}
\]

It measures the best first-order decrease available by shifting weight away from one currently active atom. At an exact minimizer of \(f\) over the correction hull, this gap is zero. Indeed, for an active atom \(v\), both small positive and negative changes along the segment between \(v\) and \(x_t\) remain in the correction hull, so the directional derivative along \(x_t-v\) must vanish.

This is restricted stationarity, not global optimality. The full Frank–Wolfe gap can still be positive because a vertex outside the correction hull may improve the objective. That is why FCFW alternates a global linear oracle with restricted correction.

### 2.3 The algorithmic loop

A basic exact iteration is:

1. obtain \(s_t\) from the global linear oracle;
2. stop if \(g_t^{\mathrm{FW}}\le\varepsilon\);
3. add \(s_t\) to \(C_t\);
4. minimize \(f\) over the new correction hull;
5. extract a positive-weight active representation of the corrected point.

The representation extraction is part of the algorithm state, not an afterthought. The convergence analysis uses the active-set gap, while future corrections use the correction set. Keep both explicit even if an implementation initially stores them in one finite map.

~~~text
global atom set A
       |
       v
 linear oracle ----> new atom s_t
       |                    |
       v                    v
global FW gap       correction hull conv(C_t ∪ {s_t})
       |                    |
 stop if small              v
                    restricted optimizer
                             |
                 point + weights + support
                             |
                             +----> next iteration
~~~

## 3. Two worked examples

### 3.1 A simplex quadratic solved by two corrections

Let \(P\) be the probability simplex in \(\mathbb R^3\), with vertices \(e_1,e_2,e_3\), and let

\[
f(x)=\frac12\|x-y\|_2^2,
\qquad
y=(0.2,0.5,0.3).
\tag{100.9}
\]

Start at \(x_0=e_1\), so the gradient is \(x_0-y=(0.8,-0.5,-0.3)\). The linear oracle chooses \(s_0=e_2\), the coordinate with smallest gradient entry. The first correction set is \(\{e_1,e_2\}\). Write a point on its edge as \(x(\alpha)=(\alpha,1-\alpha,0)\). Its objective is

\[
f(x(\alpha))
=\frac12\left((\alpha-0.2)^2+(0.5-\alpha)^2+0.3^2\right).
\]

Differentiating gives \(2\alpha-0.7=0\), so the restricted minimizer is
\(x_1=(0.35,0.65,0)\), with \(f(x_1)=0.0675\).

The new gradient is \((0.15,0.15,-0.3)\). The global oracle now returns \(e_3\), which is not in the correction set. After adding it, the correction hull is the full simplex and the exact minimizer is \(y\), with objective zero. Two global oracle calls have produced the exact solution.

At \(x_1\), the gradient pairings on the two active vertices are equal. Thus the active-set away gap is zero: the first correction is stationary within its edge. Yet the global FW gap is \(0.45\), so stopping after the restricted solve would be incorrect. This computation exhibits the division of labor between the two certificates.

### 3.2 An approximate correction can beat the line segment

Use the triangle with vertices \(a=(0,1)\), \(s=(0,-1)\), and \(c=(1,0)\), and the strongly convex objective

\[
f(x)=\frac12\|x-c\|_2^2.
\]

Start at \(x_t=a\), with a warm-start correction set \(C_t=\{a,c\}\). The gradient at \(a\) is \((-1,1)\), so both \(s\) and \(c\) minimize the linearization; choose \(s_t=s\). A line search from \(a\) to \(s\) stays on the vertical axis and is minimized at \((0,0)\), where \(f=1/2\).

The enlarged correction hull contains the point
\[
z=\tfrac14 a+\tfrac14 s+\tfrac12 c=(0.5,0).
\]
Its objective is \(f(z)=1/8\), already strictly better than the best point on the Frank–Wolfe segment. The gradient at \(z\) is \((-0.5,0)\). With the displayed positive representation, the active gap is

\[
\max_{v\in\{a,s,c\}}\langle-\nabla f(z),z-v\rangle=\frac14.
\]

Thus with \(\varepsilon=0.3\), this nonexact correction satisfies both the progress requirement and the active-gap requirement. Exact correction would return \(c\) and achieve objective zero, but the outer proof only needs the certified inequalities. The example also shows why a correction set can contain a stored atom \(c\) that is not active in the current representation \(x_t=a\).

### 3.3 What the approximate interface guarantees

For a tolerance \(\varepsilon\ge0\), the routine must return \(x_{t+1}\) and a representation with active set \(S_{t+1}\) such that

\[
f(x_{t+1})
\le
\min_{\gamma\in[0,1]}
f\bigl(x_t+\gamma(s_t-x_t)\bigr),
\qquad
g_{t+1}^{\mathrm A}\le\varepsilon.
\tag{100.10}
\]

It must also maintain \(x_{t+1}\in\operatorname{conv}(C_{t+1})\) and \(S_{t+1}\subseteq C_{t+1}\). The progress property protects the outer iteration from a poor inner solver. The gap property says the correction has removed most of the descent available within its current active support.

If the outer loop has not stopped, \(g_t^{\mathrm{FW}}>\varepsilon\), while the previous correction ensured \(g_t^{\mathrm A}\le\varepsilon\). Thus the global toward gap dominates the residual active gap. The pairwise gap is their sum, so it is at most twice the Frank–Wolfe gap. Combined with the progress guarantee, this is enough to reuse the geometric descent argument from Chapter 99. The correction itself may be approximate; the certificate is what matters.

## 4. Convergence and computational tradeoffs

### 4.1 Why the good-step count is simpler

Under the smoothness, strong-convexity, and positive-pyramidal-width assumptions of Chapter 99, a good Frank–Wolfe variant step contracts the objective error by

\[
h_{t+1}\le(1-\rho)h_t,\qquad
\rho=\frac{\mu}{4L}\left(\frac{\delta}{D}\right)^2,
\tag{100.11}
\]
where \(h_t=f(x_t)-f(x^\star)\), \(D\) is the polytope diameter, and \(\delta\) is its pyramidal width.

For AFW, a step truncated by an active-weight bound may be a drop step, so its proof counts how often such steps can occur. FCFW with the correction guarantees in (100.7) and (100.10) has a good-step guarantee at every iteration before termination. Consequently,

\[
h_t\le (1-\rho)^t h_0
\le e^{-\rho t}h_0.
\tag{100.12}
\]

This is the same geometric constant as the AFW result, but the counting argument differs. FCFW purchases a stronger per-iteration guarantee by doing more work in its correction subproblem. If \(f\) is only convex, the corresponding result is a sublinear bound; the strong-convexity assumption is what gives the geometric factor.

This theorem should not be read as a universal runtime comparison. The number of outer iterations is not the total computational cost. A restricted quadratic program over thousands of atoms can cost more than several AFW or pairwise steps. The useful comparison includes global oracle cost, correction cost, memory, and desired sparsity.

### 4.2 Growing correction sets and sparsity

If one new atom is added per iteration and no atoms are removed, then \(|C_t|\le |C_0|+t\). This makes the correction subproblem grow over time. The active support can also be smaller than \(C_t\): at an exact solution on a face of the correction hull, zero coefficients are removed from the active representation.

Carathéodory’s theorem guarantees that a point in a \(d\)-dimensional polytope has some representation using at most \(d+1\) atoms. But this existence result does not automatically give an efficient algorithm for finding a compact representation compatible with all solver certificates. In a formal development, state whether support compression is implemented, merely proved to exist, or left as an assumption of a correction oracle.

A bounded-memory method may discard old correction atoms, but then it needs a new theorem ensuring that the retained correction set still provides sufficient descent. Do not infer the FCFW rate from a memory limit alone.

## 5. Lean proof architecture

### 5.1 Make the correction certificate the boundary

A correction routine should return a package containing:

- a feasible point in the correction hull;
- a finite convex representation and its positive active support;
- the progress inequality relative to the Frank–Wolfe line search;
- an upper bound on the active-set gap;
- an updated correction set containing the new support.

These fields form a proof-facing API. An exact minimizer can construct the package using compactness, existence of a minimum, and first-order optimality. An approximate quadratic solver can construct the same package using a verified objective bound and a residual certificate. The outer convergence theorem should not inspect the solver’s internal iterations.

In Lean, it is often useful to separate a proposition describing a valid correction result from a function that computes one. The proposition supports the convergence theorem; the function needs executable data and must prove that it satisfies the proposition. This also makes it possible to state a noncomputable existence theorem independently from a verified implementation.

### 5.2 Prove global and restricted certificates separately

Define a global oracle certificate over all atoms and an active-gap certificate over the current support. The first gives the Frank–Wolfe gap and global stopping condition. The second is produced by correction. Keep the quantifier domains explicit: replacing the global oracle with a minimization over \(C_t\) changes the theorem.

A good local lemma has the shape:

> If the current FW gap exceeds \(\varepsilon\) and the correction returns an active gap at most \(\varepsilon\), then the pairwise gap is at most twice the FW gap.

This is scalar algebra after the gap identities are established. A second lemma applies the segment smoothness inequality to show that correction made at least the decrease available from the FW line search. The geometry lemma then converts that decrease into the one-step contraction. These components should not be combined into one opaque theorem.

### 5.3 Separate exact existence from approximate computation

For exact correction, formalize compactness of the finite convex hull and continuity of \(f\) to obtain a minimizer. Then prove a restricted first-order optimality statement and derive zero active gap. If the minimizer is represented with zero coefficients, define the active support by strictly positive weights before using the gap lemma.

For approximate correction, do not attempt to prove the numerical solver found an exact minimum. Instead, state the certified objective comparison and active-gap bound in its result type. If arithmetic is performed with floating-point values, use rational or interval certificates to connect computed values with real inequalities. The exact mathematical theorem consumes only the certificate.

Finally, prove the scalar recurrence (100.12) by induction. The analytic proof supplies one-step contraction; the recurrence proof knows nothing about polytopes, vertices, or Lean representations. This is the same separation between mathematical invariant and sequence algebra used throughout the optimization chapters.

## 6. Common failure modes

1. **Confusing the correction set with active support.** The former defines the restricted hull; the latter contains positive coefficients in one chosen representation.
2. **Using restricted stationarity as a stopping rule.** Only the global FW gap searches for a missing improving atom.
3. **Assuming an exact solve is required.** A certified approximate correction can satisfy the same outer proof interface.
4. **Claiming arbitrary approximate points are sufficient.** The objective progress and active-gap guarantees are essential.
5. **Forgetting the old iterate is feasible for correction.** This is needed to compare the correction with the FW segment minimum.
6. **Treating FCFW outer steps as free.** The restricted optimization cost can dominate the global oracle.
7. **Assuming the active support is automatically small.** A compact representation may require an explicit compression procedure.
8. **Mixing executable computation with existence.** Compactness proves a minimizer exists; it does not produce a verified numerical optimizer.
9. **Hiding the global atom quantifier.** A correction over the stored set cannot replace the oracle over all of \(A\).
10. **Re-proving all geometry inside the correction routine.** Keep pyramidal width and the one-step rate in the outer analysis.

## 8. Chapter summary

Fully corrective Frank–Wolfe alternates a global linear oracle with optimization over a correction hull. Exact correction is a restricted minimization problem; approximate correction is characterized by its objective progress and active-gap bound. Restricted stationarity does not certify global optimality, so the global Frank–Wolfe gap remains necessary for stopping.

The convergence proof treats correction as a black box with explicit guarantees. A good correction makes at least the progress of a line search and controls descent within the new active support. Under the same polytope geometry assumptions as away-step Frank–Wolfe, this yields a linear objective-gap rate without drop-step counting. In Lean, separate correction certificates, global oracle facts, geometric descent, and scalar recurrence.
